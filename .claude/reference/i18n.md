# Internationalization and localization: rules a card can meet and a reviewer can check

**When it is read:** at step 1 when the card names another language, country, currency, time zone, RTL or
international SEO; at step 5 when the card touches visible text, a format (number, money, date, unit), a
layout with text, a text input, language negotiation or a translation flow; and always, for the **N0** rules,
when the card formats a value or stores an instant. **How:** only the sections the card touches, with `Read`
and a line range of the heading; never whole. The plan names the rule IDs that apply and the level.
Examples are `node-ts` (`Intl`, ICU MessageFormat, Playwright); each rule brings its generic equivalent.
**Libraries and tools are options, not obligations.** **[NV] marks guidance not verified**: a hypothesis,
never the only evidence of a `meets`. Neighboring topics are cited by prefix: accessibility (`A11Y-*`) in
`reference/accessibility.md` (module ui), storage of money and instants (`DB-MOD-*`) in `reference/database.md` (module data). How each
rule is checked: `J` judgment with written evidence, `C` a command that exits 0 or not, `T` an automated test.
The `rg` examples assume code under `src/`; they are syntax to validate on first use, not tried against a repo.
Source numbers `Bn` are in Sources. Evidence marks: **[V]** checked in the source, **[V-sec]** only in a
secondary source, **[V-exec]** checked by running the example on Node v24.13.1 with ICU 78.2.

The language of the repo's own artifacts (`CLAUDE.md`: the work speaks the repo's language) is not
internationalization of the product and never activates the module.

The rules carry a level (N0, N1, N2, defined in the first section after the table). The plan states the level
and, from N2, the locale matrix (template c.4); without a matrix there is no N2.

## Levels

- **N0 — base (always, with or without the module):** formats with `Intl` and an explicit locale, instants in
  UTC, Unicode text in NFC, identifiers never compared with locale-dependent case. It is correctness, not
  localization: it applies to a product with a single language.
- **N1 — prepared for i18n:** N0 + externalized strings with context, plurals by category, no concatenation,
  logical CSS properties, a layout that tolerates expansion, pseudo-localization in CI.
- **N2 — localized:** N1 + more than one locale delivered, language negotiation, a translation and review
  flow, screenshots per locale, `hreflang` if there are public pages.

## Activation signals

`tools/signals.mjs` reads the strong ones (dependency, catalog path, framework config, more than one `lang`
in the markup, or the card asking for a language) and `doctor.mjs` prints them as
`module i18n — pre-marked: <evidence>`; the person chooses the module at install (`kit.json`). The weak ones
below are judged by whoever plans the card and decide the level, not the module.

**Strong, one is enough to activate:**

| Signal | Where to look |
|---|---|
| An i18n dependency | `package.json`: `i18next`, `react-i18next`, `next-i18next`, `next-intl`, `react-intl`, `@formatjs/*`, `@lingui/*`, `vue-i18n`, `@nuxtjs/i18n`, `@angular/localize`, `@ngx-translate/core`, `@fluent/*`, `svelte-i18n`, `typesafe-i18n`, `rosetta`, `node-polyglot`; others: `Babel`/`django.utils.translation`/`flask-babel` (Python), `Microsoft.Extensions.Localization` (.NET), `ResourceBundle`/`MessageSource` (Java) **[NV full list]** |
| Catalogs | `**/locales/**`, `**/i18n/**`, `**/lang/**`, `**/translations/**`, `**/messages/*.json`, `public/locales/**`; files `*.po`, `*.pot`, `*.mo`, `*.ftl`, `*.xlf`, `*.xliff`, `*.arb`, `*.xcstrings`, `*.strings`, `*.lproj/`, `res/values-*/strings.xml`, `*.<culture>.resx` |
| More than one language catalog | two or more directories or files with distinct BCP 47 tags: level N2 |
| Framework config | `next.config.*` with `i18n:`; `nuxt.config.*` with `i18n`; `angular.json` with `"i18n"`; `lingui.config.*`/`.linguirc`; `i18next-parser.config.*`; `crowdin.yml`, `lokalise.yml`, `.phrase.yml`, `l10n.toml` (Pontoon) **[NV TMS config names]** |
| Markup | `hreflang=` in templates; `dir="rtl"` or `dir="auto"`; two or more distinct `<html lang>` values |

**Weak, they add up, none activates alone (two or more: `candidate`):** `Intl.` or `toLocale*` (formats, not
languages); `currency`, `locale`, `language`, `timezone`/`time_zone` columns or fields in migrations or models;
more than one currency or country in fixtures or seeds; `Accept-Language` read on the server; CSS with `:dir(`
or `[dir=rtl]`.

**From the card (read by step 1, not by `doctor`):** another language, a translation, “multi-country”, a
country or currency other than the repo's, users' time zone, RTL, Arabic or Hebrew, international SEO or
`hreflang`. With no repo signal, that puts the module at N1 at least; if the card does not say which locales,
it is an ambiguity.

**Never activates:** the language of the repo's artifacts, nor a single `<html lang>`.

## 1. Activation and scope (ACT)

**I18N-ACT-01** — On activating the module, write in the plan the level (N0/N1/N2) and the matrix of supported locales (template c.4); without a matrix there is no N2. Level N1+ · How J+C · criterion I32 · Check: the plan has the section and the matrix; `rg -n "## Locales" specs/<card>/plan.md`. If the card says “in English and Portuguese” or “for clients in Mexico”, the matrix is a requirement; if it does not say and the repo has no signals, it is an ambiguity `<ID>-AMB-NN`, not an assumption · Source B1, B32.

**I18N-ACT-02** — The N0 rules apply in every repo, active module or not. Level N0 · How C · criterion none · Check: the `rg` of I18N-FMT-01, I18N-FMT-06 and I18N-INP-07 run the same · Source B17, B18, B11, B25.

**I18N-ACT-03** — If the card names a second language, another country or a foreign currency, take the repo to N1 before building more UI; measure the delay with the inventory of hardcoded strings. Level N1 · How C · criterion none · Check: the count of `i18next/no-literal-string` (or equivalent) is recorded in the plan and does not grow between cards; node-ts `npx eslint src --rule '{"i18next/no-literal-string":"error"}' -f json`. The relative cost of doing it late **[NV]**: no published measurement was found; the argument is that each new unexternalized screen adds to the inventory to migrate by hand · Source B32.

## 2. Externalizing strings (STR)

**I18N-STR-01** — No user-visible text lives in the code: it goes to a catalog per locale. Level N1 · How C+T · criterion I27 · Check: a literal-string linter and the pseudo-locale (whatever appears unmarked is hardcoded). node-ts (React) `eslint-plugin-i18next` → `i18next/no-literal-string: error`, with FormatJS `formatjs/no-literal-string-in-jsx`; generic Android Lint `HardcodedText` **[NV]**; in any stack, the pseudo-loc test of I18N-TST-02. Includes `aria-label`, `alt`, `title`, `placeholder`, validation messages, toasts, emails and PDFs; excludes logs, IDs and configuration keys · Source B30, B31, B26.

**I18N-STR-02** — Choose one identifier strategy per repo and keep it: a stable semantic key (`checkout.payButton.label`) or source text plus context (gettext/Lingui); when the meaning changes, the ID changes. Level N1 · How J+C · criterion none · Check: review of the catalog diff; a message whose source text changed meaning under the same ID is a defect (old translations lie). A semantic key describes place and function, not the text (`errors.emailTaken`, not `thisEmailIsTaken`); with source text, context is mandatory for short strings (I18N-STR-04) · Source B26, B35.

**I18N-STR-03** — Every message carries a description for the translator: where it appears, what it does, a character limit if any, and what each placeholder is. Level N1 · How C · criterion I27 · Check: FormatJS `formatjs/enforce-description`; PO `#.` before each `msgid`; Fluent `#` comment; Android XML comment; `.resx` `<comment>` **[NV]**; node-ts `intl.formatMessage({ id: 'cart.items.count', defaultMessage: '{count, plural, =0 {Your cart is empty} one {# item} other {# items}}', description: 'Cart heading. count = number of items (integer >= 0). Max 30 characters.' }, { count })` · Source B31, B26, B30.

**I18N-STR-04** — Do not reuse a string in two contexts even if the source text matches (“Open” of a menu and of a printer, “Yes” of a dialog and of a state). Level N1 · How J · criterion I27 · Check: review for one ID used from two components of different function; `rg -c "t\('common\.(yes|no|open|ok)'" src/` finds the most used generic ones · Source B31, B26, B35.

**I18N-STR-05** — Never build a sentence by concatenating fragments or interpolating translated text inside another: one whole sentence per message, with named placeholders and the markup inside the message. Level N1 · How C+T · criterion I27 · Check: `rg -n "t\([^)]*\)\s*\+|\+\s*t\(|\`\$\{t\(" src/` and `formatjs/prefer-full-sentence`; the pseudo-loc test shows concatenation as split brackets. Bad `t('deleted') + ' ' + n + ' ' + t('files')`; good `t('files.deleted', { count: n })`. Links and bold: `'Accept the <link>terms</link>'` with rich-text tags (FormatJS) or `data-l10n-name` (Fluent), never `t('accept') + <a>{t('terms')}</a>` · Source B26, B31, B2, B30.

**I18N-STR-06** — Choose the plural form by CLDR category (`Intl.PluralRules` or a `plural` message), never with `n === 1`; every `plural`/`select` has `other`. Level N1 · How C+T · criterion I28 · Check: `rg -n "(===?|!==?)\s*1\s*\?|length\s*(===?|>)\s*1\s*\?" src/ --glob "*.{ts,tsx,js,jsx,vue,svelte}"` (reviewed by hand: not every `=== 1` is a plural); `formatjs/enforce-plural-rules`; the test renders the message with `count` 0, 1, 2, 5, 21, 1.5 in `ar`, `ru` and the source locale and gets a variant distinct from the fallback in each category. `=0 {…}` is an optional exact case, not a category; ordinals with `selectordinal` / `PluralRules({ type: 'ordinal' })`. Arabic has six categories and Russian maps 21 to `one` [V-exec] · Source B13, B18, B35.

**I18N-STR-07** — If the text depends on gender or another attribute, use `select` with `other` and pass the attribute as explicit data; never deduce it from the name or the title. Level N1 · How J+T · criterion I28 · Check: the message with `gender` absent or unknown falls to `other`, with neutral text · Source B35, B8.

**I18N-STR-08** — Values inside a message are formatted by locale (in the message with `{x, number}`/`{d, date}`, or before with `Intl`), never interpolated raw. Level N1 · How C · criterion I28 · Check: `rg -n "\{\{?\s*(price|amount|total|date|importe)\b" src/locales/` and verify the argument arrives formatted or typed in the message · Source B35, B17.

**I18N-STR-09** — Separate what is shown from what is used: IDs, enums, configuration keys and technical names are not translated; the UI shows a separate display name. Level N1 · How J+C · criterion I27 · Check: no `switch` or comparison over translated text; `rg -n "===?\s*t\(" src/` · Source B31.

**I18N-STR-10** — Use as catalog format what your library supports as stable (ICU MessageFormat 1, Fluent, PO, the platform's native); do not adopt MessageFormat 2 in production until your runtime marks it stable. Level N1 · How J · criterion none · Check: the plan names the format and the library version. The MF2 specification is stable in LDML (CLDR 47 onward) but ICU4C is a technology preview, ICU4J has the core API as draft, and `Intl.MessageFormat` is Stage 1 in the TC39 README [V / V-sec]; a blog claims Stage 2, unconfirmed · Source B14, B15, B16.

**I18N-STR-11** — Errors and messages coming from the server travel as a stable code plus parameters; the client translates them. If the server must write (emails, PDF, notifications), it receives the recipient's locale, not the process's. Level N1 · How T · criterion I27 · Check: an API test: the error response carries `code` and `params`, and the same error rendered in two locales gives two texts. **[NV]** as a named practice: derived from B31, not written so in any source · Source B31, B18.

## 3. Formats (FMT)

**I18N-FMT-01** — Always pass the locale (and the zone, for dates) to every formatting: no `toLocaleString()` or `new Intl.X()` without arguments; the locale is resolved once per request/session and injected. Level N0 · How C · criterion I26 · Check: `rg -n "\.toLocale(String|DateString|TimeString|UpperCase|LowerCase)\(\s*\)|new Intl\.\w+\(\s*(\)|undefined|\[\s*\])" src/` → 0. node-ts `new Intl.NumberFormat(locale, { style: 'currency', currency })` with the user's `locale`; generic explicit `CultureInfo` (.NET), explicit `Locale` (Java), `FormatStyle` with locale (Swift) **[NV]**. Without `locales`, the implementation default is used (here `en-US`: `(1234.5).toLocaleString()` → `1,234.5`) [V-exec] · Source B17, B18.

**I18N-FMT-02** — Create each formatter once and reuse it in lists and loops. Level N1 · How C+J · criterion none · Check: `rg -n "\.map\([^)]*new Intl\." src/`; review `new Intl.` inside row render; node-ts `const fmt = useMemo(() => new Intl.NumberFormat(locale, opts), [locale])` · Source B18.

**I18N-FMT-03** — Do not use `Intl` output in logic (compare, parse, store); in tests, fix locale and zone, and compare by parts or normalizing spaces. Level N0 · How C+T · criterion I26 · Check: `rg -n "format\([^)]*\)\s*===|\.split\(['\"][,.]['\"]\)" src/` over formatted results; the test uses `formatToParts` and checks `type: 'currency'`, `'decimal'`, `'group'` instead of the literal string, or `s.replace(/[  ]/g, ' ')` before comparing. ICU uses U+00A0 and U+202F as separators in several locales **[NV]**; `ar-EG` dates carry U+200F marks between parts [V-exec] · Source B18.

**I18N-FMT-04** — Store the amount as a decimal (or an integer in minor units) next to its ISO 4217 code; format with `style: 'currency'` and an explicit `currency`; the currency is data, not deduced from the locale; business rounding is done in the domain, not on display. Level N0 · How C+T · criterion I26 · Check: `rg -n "toFixed\(2\)|['\"][$€]\s*['\"]\s*\+|\+\s*['\"]\s*[$€]" src/` → 0; the test shows the same amount in `es-AR`/ARS, `en-US`/USD, `ja-JP`/JPY (0 decimals) and `de-CH`/CHF (`$ 1.234,50`, `￥1,235`, `CHF 1'234.50` [V-exec]). An `es-AR` customer paying in EUR sees EUR formatted as `es-AR`. Cash rounding (CHF to 0.05) and bankers' rounding: a decision of the requirement **[NV CLDR cash-rounding data]** · Source B19; see `reference/database.md` (module data) DB-MOD-05.

**I18N-FMT-05** — Store instants in UTC and show them in the user's zone by passing `timeZone` (an IANA ID); floating dates (birthdays, “of the day” expirations) are stored without a zone; future events at local time store local time plus the IANA zone. Level N0 · How C+T · criterion I26 · Check: `rg -n "DateTimeFormat\([^)]*\)" src/ | rg -v timeZone` (reviewed); ISO 8601 with `Z` or an offset in APIs: `rg -n "toISOString|toJSON" src/`. node-ts `new Intl.DateTimeFormat(locale, { dateStyle: 'medium', timeStyle: 'short', timeZone: user.timeZone })`. A birthday is `"1990-05-04"` as a string or `Temporal.PlainDate`, never `new Date("1990-05-04")` (interpreted as UTC, shifts a day in negative zones **[NV this session]**). Never `-03:00` as a zone: an offset carries no daylight-saving rules · Source B11; see `reference/database.md` (module data) DB-MOD-06.

**I18N-FMT-06** — On the server do not use the process's zone or locale: no `getHours()`, `getDate()`, `setHours(0,…)` or `toLocaleDateString()` for business logic; run the tests with a `TZ` other than UTC. Level N0 · How C+T · criterion I26 · Check: `rg -n "\.(get|set)(Hours|Date|Day|Month|FullYear|Minutes)\(" src/ --glob "!**/*.test.*"` → each one justified (or `getUTC*`); CI runs the suite twice, `TZ=UTC` and `TZ=America/Argentina/Buenos_Aires` (or `Pacific/Kiritimati`, UTC+14, which exposes day cutoffs); also `LANG=tr_TR.UTF-8` **[NV effect of `LANG` on Node's `Intl`]** · Source B11, B17.

**I18N-FMT-07** — Units with `Intl.NumberFormat({ style: 'unit' })`; the measurement system (metric/imperial) is a preference per region or user, not an assumption. Level N1 · How T · criterion none · Check: `5 km` in `es` and conversion to miles only if the preference asks. Per-region preference in CLDR **[NV]** · Source B19.

**I18N-FMT-08** — Lists, relative time, durations and names of languages/countries/currencies come from `Intl` (`ListFormat`, `RelativeTimeFormat`, `DurationFormat`, `DisplayNames`), not from hand arrays or `join(', ')`. Level N1 · How C · criterion none · Check: `rg -n "join\(['\"],\s*['\"]\)|hace \$\{|ago\`|\['Argentina',|\['Enero'|\['January'" src/`. `ListFormat('es')` → `a, b y c`, `RelativeTimeFormat('es',{numeric:'auto'}).format(-1,'day')` → `ayer`, `DisplayNames(['es']).of('pt-BR')` → `portugués de Brasil` [V-exec]; `DurationFormat` is Baseline 2025 [V] · Source B17.

**I18N-FMT-09** — For new dates you may use Temporal with a polyfill or behind an own abstraction; do not depend on it natively while stable Safari does not ship it. Level N1 · How J · criterion none · Check: **status:** Stage 4 (TC39 finished proposals, publication expected 2027), Chrome/Edge 144+, Firefox 139+, Safari only in Technology Preview, about 70 % global; absent in Node 24 (`typeof Temporal === "undefined"`) [V / V-exec]; that Node 26 ships it **[NV]**. Temporal does not change I18N-FMT-05: `Instant` for instants, `PlainDate` for floating, `ZonedDateTime` with an IANA ID for future local-time events · Source B24.

**I18N-FMT-10** — Numbers typed by the user are parsed with the decimal separator of their locale (obtained from `formatToParts`), or requested with a control that does not depend on the separator. Level N1 · How T · criterion none · Check: `1.234,5` in `es-AR` and `1,234.5` in `en-US` give the same value; see `reference/accessibility.md` (module ui) A11Y-FRM-08 for `inputmode`. `Intl` ships no parser **[NV as an ECMA-402 claim]** · Source B18.

## 4. Layout (LAY)

**I18N-LAY-01** — Design for text to grow: no fixed width or height in text containers (buttons, tabs, cells, chips, menus), wrap allowed; size against +40 % on average and ×2–3 in strings of 10 characters or fewer. Level N1 · How T+J · criterion I29 · Check: a Playwright test in the pseudo-locale: no element with text has `scrollWidth > clientWidth` with `overflow` other than `visible` unless marked `data-truncate` (`page.$$eval('button, [role=tab], th, td, label, a', els => els.filter(e => e.scrollWidth > e.clientWidth + 1 && getComputedStyle(e).overflow !== 'visible' && !e.hasAttribute('data-truncate')))` → `[]`); `node .claude/tools/overflow.mjs` (profile web) is the kit's tool for the same measurement; generic `rg -n "width:\s*\d+px" src/ --glob "*.{css,scss}"` in components with text, Xcode test plans with a long pseudolanguage, `en-XA` on Android. Average expansion English → European languages (IBM table): ≤10 characters 200–300 %; 11–20 180–200 %; 21–30 160–180 %; 31–50 140–160 %; 51–70 151–170 %; >70 130 % · Source B9, B31, B29, B30.

**I18N-LAY-02** — Use logical properties (`margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `text-align: start`, `border-start-start-radius`) instead of `left/right`; physical ones only for what does not depend on text direction. Level N1 · How C · criterion I29 · Check: `npx stylelint "src/**/*.css"` with `property-layout-mappings: "flow-relative"` (built in, [V-sec]) or `csstools/use-logical: "always"` (the plugin is in maintenance mode and points to the built-in rules). Without a linter: `rg -n "(margin|padding|border)-(left|right)\b|^\s*(left|right)\s*:|text-align:\s*(left|right)|float:\s*(left|right)" src/ --glob "*.{css,scss,less}"`. Tailwind `ms-*/me-*/ps-*/pe-*/start-*/end-*` instead of `ml-/mr-/pl-/pr-/left-/right-` **[NV]**: `rg -n "\b-?(ml|mr|pl|pr|left|right|rounded-[lr]|border-[lr])-" src/ --glob "*.{tsx,jsx,vue,html}"`. Generic `leading/trailing` (SwiftUI, Auto Layout), `start/end` (Android) · Source B22, B6, B23, B29.

**I18N-LAY-03** — The base direction goes in the markup (`<html lang="ar" dir="rtl">`), never in CSS; text coming from the user or from data is isolated with `dir="auto"` on the wrapping element or with `<bdi>`; in attributes (`title`) FSI U+2068 … PDI U+2069 is used. Level N2 · How C+T · criterion I30 · Check: `rg -n "direction:\s*rtl|unicode-bidi" src/ --glob "*.{css,scss}"` → reviewed; the test in `ar`: `document.documentElement.dir === 'rtl'`; user names and table values inside `<bdi>` or with `dir="auto"`; free-text `input`/`textarea` with `dir="auto"` · Source B6, B7.

**I18N-LAY-04** — In RTL mirror what indicates reading or navigation direction (back/forward, advance chevrons, linear progress bars, illustrations with direction); do not mirror a clock or circular refresh arrows, playback controls and their bar, logos, check marks or numbers. Level N2 · How T+J · criterion I30 · Check: a screenshot in `ar`/`he` of each view with directional icons, reviewed against the list; node-ts an icon marked `data-directional` plus `:dir(rtl) [data-directional] { transform: scaleX(-1) }` (`:dir()` broad support **[NV]**). The Material Design pages did not render; the list comes from search results and the Wikimedia Codex style guide [V-sec] · Source B28.

**I18N-LAY-05** — The font stack covers the scripts of the locale matrix (with fallback by `unicode-range` or system fonts) and the line height leaves room for diacritics and tall scripts. Level N2 · How T+J · criterion I29 · Check: a screenshot in the pseudo-locale padded with other scripts and in each real script of the matrix: no tofu or vertical clipping. The kit ships Inter Variable (`reference/components.md`, module ui), whose coverage of Arabic, Hebrew and CJK is **[NV]** · Source B31.

**I18N-LAY-06** — Truncate in CSS (`text-overflow: ellipsis`, `line-clamp`) with the full text available; if you must cut in code, cut by graphemes with `Intl.Segmenter`, never with `slice` over translated or user text. Level N1 · How C · criterion I29 · Check: `rg -n "\.(slice|substring|substr)\(0,\s*\d+\)" src/` over visible strings. A family emoji plus `é` is 2 graphemes and 10 UTF-16 units [V-exec] · Source B18.

**I18N-LAY-07** — No text inside images; illustrations and examples reviewed for cultural bias. Level N1 · How J · criterion none · Check: review of new assets · Source B2.

**I18N-LAY-08** — Change case for display with the locale (`toLocaleUpperCase(locale)` or `text-transform` with a correct `lang` on the element); never use `toUpperCase()` over text shown in a language other than the source. Level N1 · How C · criterion I29 · Check: `rg -n "\.to(Upper|Lower)Case\(\)" src/` → each is an identifier (I18N-INP-07) or is changed. `"istanbul".toLocaleUpperCase("TR")` → `İSTANBUL`, `"TITLE".toLocaleLowerCase("tr")` → `tıtle` [V-exec]; that `text-transform` respects `lang` **[NV]** · Source B21.

## 5. Data entry (INP)

**I18N-INP-01** — Ask for the name in a “Full name” field (plus “What should we call you?” if needed); if it must be split, “Given names” and “Family name” without requiring a family name; accept accents, apostrophes, hyphens, spaces and any script; do not change case. Level N0 · How T · criterion none · Check: accepted and returned intact `Zoë O'Brien-Núñez`, `李小龍`, `Sukarno` (no family name), `van der Waals`, `محمد`; `rg -n "\[a-zA-Z\s\]|\^\[A-Za-z" src/` in name validations → 0; autofill: A11Y-FRM-02 · Source B8.

**I18N-INP-02** — Addresses follow the format of the chosen country; no postal code, province or street number mandatory for everyone; if there is no per-country format, a free multiline field plus country. Level N1 · How T+J · criterion none · Check: an address from a country without postal code can be saved. **[NV]**: no primary source was opened (Google `libaddressinput` / address data) · Source none.

**I18N-INP-03** — Parse and validate phones with libphonenumber (or a rewrite such as `libphonenumber-js`) with the user's region by default; store in E.164 and show formatted. Level N1 · How T · criterion none · Check: `011 15-2345-6789` with region `AR` and `+54 9 11 2345-6789` normalize to the same E.164; `rg -n "tel.*\\\\d\{10\}|phone.*regex" src/` → home-made validations. Storing E.164 is a convention, not something the library says **[NV as a recommendation of the source]** · Source B34.

**I18N-INP-04** — UTF-8 end to end (HTML, API, database, files) and length limits in characters, not bytes. Level N0 · How C+T · criterion I26 · Check: `rg -n -i "charset=(?!utf-8)" -P src/ templates/`; columns: DB-MOD-05, and `varchar(n)` counted in bytes in some engines **[NV]**; the test stores and reads `李小龍 👨‍👩‍👧` without loss · Source B2, B8.

**I18N-INP-05** — Normalize to NFC the text that comes in and before comparing or indexing; NFKC only for identifiers (user name, slug), never over free text. Level N0 · How T · criterion I26 · Check: node-ts `input.normalize('NFC')` at the edge (DTO/validator); the test registers `José` with `é` and finds it by searching `é`. `"é" !== "é"` until normalized [V-exec] · Source B25.

**I18N-INP-06** — Sort with `Intl.Collator(locale)` (with `numeric: true` when the text has numbers) and search without accents or case with `Collator(locale, { usage: 'search', sensitivity: 'base' })` or with the database's collation/`unaccent`. Level N1 · How C+T · criterion none · Check: `rg -n "\.sort\(\s*\)|localeCompare\(\s*\w+\s*\)|\.sort\(\(a,\s*b\)\s*=>\s*a\s*[<>]" src/` → review those that sort visible text; the test: `['Ñandú','zorro','nube','árbol','avión']` sorts `árbol, avión, nube, Ñandú, zorro` in `es` (default `.sort()` leaves `Ñandú` and `árbol` last) and searching `jose` finds `José` [V-exec]. In the database, accent-free order and search depend on the collation **[NV]**; see `reference/database.md` (module data) DB-IDX · Source B20, B18.

**I18N-INP-07** — Compare identifiers, keys, protocols, normalized emails and file names ordinally or invariantly, never with locale-dependent case. Level N0 · How C · criterion I26 · Check: `rg -n "toLocale(Upper|Lower)Case\(\s*\)" src/` → 0. node-ts: `a.toLowerCase() === b.toLowerCase()` for ASCII identifiers is fine because `toLowerCase` does not depend on the locale; what is forbidden is `toLocaleLowerCase()` without a fixed locale in that comparison. .NET `StringComparison.Ordinal(IgnoreCase)`; Java `toLowerCase(Locale.ROOT)` **[NV]**. The Turkish I breaks `"FILE:"` matching in a Turkish culture (a security example in the .NET guide) · Source B32, B21.

**I18N-INP-08** — Count and limit the visible length by graphemes and validate the same limit, in the same unit, on client and server. Level N1 · How T · criterion none · Check: a composed emoji counts as 1 in the counter and the server does not reject it for exceeding `maxLength` · Source B18.

## 6. Language detection and choice (NEG)

**I18N-NEG-01** — Resolve the language in this order: stored explicit choice (profile, cookie) → language of the URL → `Accept-Language` → default; offer a visible selector with each language written in its own language. Level N2 · How T · criterion I32 · Check: with cookie `pt-BR` and header `es`, `pt-BR` is served; without a cookie, `es`; with header `xx`, the default. `DisplayNames([tag]).of(tag)` gives the autonym **[NV as a use]**. Geolocating by IP to pick the language is not covered by the sources read **[NV]**; if used, only as a suggestion · Source B10, B2.

**I18N-NEG-02** — Negotiate with canonical BCP 47 tags and a fallback chain (`es-AR` → `es` → source language); use the shortest tag that distinguishes. Level N2 · How T · criterion I32 · Check: `getCanonicalLocales(['EN-us','zh-hant-tw'])` → `en-US, zh-Hant-TW` [V-exec]; node-ts `Intl.NumberFormat.supportedLocalesOf(requested)` and own fallback, or `@formatjs/intl-localematcher` **[NV name]**; the RFC 4647 algorithm details **[NV]** · Source B4, B5, B17.

**I18N-NEG-03** — `<html lang>` states the language of the served content (not the preference) and changes when the language changes in an SPA; fragments in another language carry their `lang`. Level N0 · How T · criterion I5 · Check: see `reference/accessibility.md` (module ui) A11Y-SEM-06 (not repeated); I5 covers the page language (WCAG 3.1.1), not the change of `lang` on switching language · Source B2, B6.

**I18N-NEG-04** — Treat language, formatting region, currency and time zone as independent preferences. Level N2 · How J+T · criterion I32 · Check: language `es`, format `de-DE`, currency EUR, zone `Europe/Berlin` are respected together · Source B10, B19.

**I18N-NEG-05** — If there are indexable public pages per language: one URL per language, reciprocal `hreflang` on all (itself included), absolute URLs, `x-default`, ISO 639-1 codes (+ optional region), through a single mechanism. Level N2 · How T · criterion I32 · Check: a test requests each version and checks that the set of `<link rel="alternate" hreflang>` is identical on all, absolute, with `x-default`, and that each target answers 200 and links back · Source B33.

**I18N-NEG-06** — If the server chooses content by `Accept-Language`, it answers with `Vary: Accept-Language` (or redirects to the language's URL) so no cache serves one language to someone who asked for another. Level N2 · How T · criterion none · Check: **[NV]** (HTTP `Vary` semantics, not opened this session); the test inspects the header · Source none.

## 7. Translation flow (FLW)

**I18N-FLW-01** — One catalog per locale and namespace, in a format that supports plurals, context and comments; the source locale is the single source of truth and lives in the repo. Level N1 · How C · criterion none · Check: file structure of template c.1; no UI text outside it (I18N-STR-01) · Source B26, B27, B30, B31, B35.

**I18N-FLW-02** — The source-locale catalog has every key; a missing key in another locale falls through the fallback chain and is reported, never shows the raw key in production; in CI it is an error. **I18N-FLW-03** — Message extraction runs in CI and its diff is empty: the source catalog is in sync with the code. **I18N-FLW-04** — A TMS (Crowdin, Lokalise, Phrase, Weblate, Pontoon…) is optional; if used, it syncs against the repo and the repo stays the source; every machine translation goes through a speaker's review before reaching a customer. **I18N-FLW-05** — Mark what is not translated (brand, product names, code) with the format's mechanism: Fluent terms, `{Locked}`, `<xliff:g>`, `translatable="false"`. **I18N-FLW-06** — Generate a pseudo-locale in dev and CI with accents, +40 % expansion (more on short strings), delimiters at start and end, and an RTL variant; its tag is private and can never be real (`qps-ploc`, `en-XA`, `ar-XB`, `x-pseudo`). ## 8. Testing (TST)

**I18N-TST-01** — A CI command compares the keys used in the code with each catalog and fails on missing keys, extra keys, or placeholders different from the source. ### c.3 Pseudo-localization plan

```markdown
## Pseudo-localization
- Tag: `en-XA` (messages) and `ar-XB` (RTL). Private: never matching a real locale.
  Formats (`Intl`) are tested with real locales: `de-DE` (long), `ar-EG` (RTL, digits).
- Transformation, per source-catalog message, without touching placeholders or tags:
  1. Letters → accented variants (a→á/å/ä…), digits untouched.
  2. Expansion: +40 % padding if 20 characters or more; ×2 if 11–20; ×3 if 10 or fewer.
     The padding mixes Greek, Cyrillic and CJK to test fonts.
  3. Delimiters `[` … `]` at start and end (clipping and concatenation become visible).
  4. Optional: a short hash suffix of the key to find it.
  RTL: character order reversed and `dir="rtl"` on `<html>`.
- Where: generated in the dev/CI build (not versioned), selectable with `?lng=en-XA` or a cookie;
  never in the production build.
- What runs: I18N-TST-02 per view and per state (open modal, visible error), and screenshots in `ar-XB`.
- Exit criterion: 0 unmarked texts except the allow list (brand, user data), 0 clips except
  `data-truncate`, RTL screenshots reviewed.
- Declared limits: it does not detect bad translations, strings shorter than the source or grammar
  problems; it does not replace validating the translated app.
```

### c.4 Matrix of supported locales

```markdown
## Locales
| BCP 47 tag | Language | Region | Currency (ISO 4217) | Short date (example) | Default zone | Direction | Plural (CLDR categories) | Source/review | Status |
|---|---|---|---|---|---|---|---|---|---|
| es-AR | Spanish | Argentina | ARS | 15/1/2026 | America/Argentina/Buenos_Aires | ltr | one, many, other | source | complete |
| ar-EG | Arabic | Egypt | EGP | ١٥/١/٢٠٢٦ | Africa/Cairo | rtl | zero, one, two, few, many, other | n/a | out of scope |
Fallback: es-AR → es → es-AR (source). Pseudo: en-XA, ar-XB (dev/CI only).
```
